# Bash box interpreters and wrapper forms

Verified 2026-10-22 on CG (temperature-code-golf test 1 probe `command -v` + `ls /usr/local/bin`, dont-panic test 3 games 910948576, 910948586):

- on PATH: perl 5.34, python3 3.11.5, `/bin/lua`, `/bin/php`; `python` = python2 (`/usr/bin/python2`), no gain over `python3`
- ruby only at `/usr/local/bin/ruby` (not on PATH); no node
- a bash host needs no wait: a foreground command already shares stdin/stdout and blocks; io and interactive identical
- forms that pass on CG (all generated by `agent/wrap/bash/`):
  - inline `perl -lnE'..'`, `python3 -c'..'`, `lua -e'..'`, `php -ddisplay_errors= -r'..'`, `/usr/local/bin/ruby -e'..'`; no space needed between the flag and the quote
  - `exec python3 -x $0` + newline + python body: `-x` skips line 1 of the script, 19 B overhead, no quote escaping (beats `-c'..'` once the body has 2+ single quotes)
  - `exec perl -x $0` + `#!perl` line + body (23 B overhead); `-E` is refused on the `#!` line ("Can't emulate -E on #! line"): put `-M5.01` (gives `say`) on the command line instead
  - heredoc on fd 3 `perl /dev/fd/3 3<<\E` + newline + body, no terminator: bash warns on stderr (test-game `error` field shows the warning) but `success` stays true; 20 B overhead for perl
- php file forms (local only, unverified on CG): the spawned CLI php has short tags off, so `<?` needs `<?php `; reading the script from a pipe (`/dev/fd/3` heredoc) php eats the first byte (shebang probe without rewind): put a throwaway newline before `<?php`
- `php` without `-ddisplay_errors=` prints warnings on stdout (local referee, same as `knowledge/lang/_shared/system-wrapper.md` Lua box note)
- local trap: the bash launcher PATH holds perl, python3, lua only, so bare `php` forms fail locally although CG has php on PATH; `/bin/php` passes both (+5 B)
